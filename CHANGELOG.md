## [0.3.0] - Unreleased

### Added

- **Transaction log / checkpoint / flush-map / reserved-log parsing** (`src/ese/log/`): `LogFile` (log file header + data sectors), `CheckpointFile` (`.chk`), `FlushMap` (`.jfm`, header only), and `EseLogSet` (directory discovery of a complete file set, grouped by shared `signLog` rather than by filename, since a database's log-set base name — e.g. `SRU` for `SRUDB.dat` — is not derivable from the database's own filename).
- `LogSector`/`SectorClass` (`Live`/`Shadow`/`Stale`/`Unwritten`/`Unrecognized`): every log data sector self-identifies its own position, which distinguishes a torn-write shadow copy from residual data left behind by a recycled generation. **Verified against `artifacts/sru/`**: `SRU.log` carries 32 KiB of residual generation-180 data past its own write frontier, and `SRUtmp.log` holds a *complete* generation 181 whose archived file no longer exists.
- `EseLogSet::report()` — a log-set integrity report (`LogSetReport`) with a `#[non_exhaustive]` `LogAnomaly` enum. Every variant carries observed-vs-expected values (never prose) and a `benign_explanation()` stating, in the type itself, the innocent explanation an examiner should rule out first.
- Two checksum algorithms, verified byte-exactly against every fixture in `artifacts/sru/`: the log file header checksum (`0x89abcdef ^ XOR(u32 @ 4..cbSec)`) and the checkpoint checksum (`XOR(u32 @ 4..end)`). `ChecksumVerdict::NotVerified` is a first-class outcome for structures with no known algorithm (a `.jfm` header, a log data sector) — never fabricated as `Match`.
- `Lgpos` (log position: `{generation, sector, byte}`) and `Signature` (the 28-byte instance identity shared by a database, its log files, and its checkpoint) — the two linchpin types the whole file-set feature is built on.
- `LogTimestamp`, a three-state timestamp (`Unset`/`Present`/`Invalid`) that never silently degrades an unparseable value to a fabricated instant, unlike `Header::log_time_or_epoch`. `Header::shutdown_time()`/`attach_time()`/`detach_time()` expose it for case-facing use.
- **Value recovery** (`src/ese/recovery/`), exposed through `forensic_rs::traits::db::RecoverRows`: `EseDb::as_recovery()` always returns `Some(self)`, and `recovered_rows(table)`/`slack_rows(table)` return an ordinary `Box<dyn ForensicRows>` — recovered rows travel through the same cursor type any consumer already knows how to read, distinguished by `allocated() == false` and a real per-row `recovery()`/`locus()`, not a parallel type. `recovered_rows` finds rows still addressable via a page's tag array but marked `TAG_DEFUNCT` (deleted); `slack_rows` finds candidate records in a live page's unallocated slack, computed via `forensic_rs::recovery::slack_regions` (which also finds gaps *between* two live records, not just the single trailing gap the first version of this feature found). Both decode through the same schema-validated path the live row iterator uses, validated against only the schema of the table that owns the page, and both gate on `forensic_rs::recovery::looks_like_padding` before ever attempting a decode. Slack candidates additionally apply a stricter bar (two meaningful columns, not one) since — unlike a defunct tag, which the engine itself wrote — a slack candidate has no governing marker; see `recovery::validate::is_meaningful` for why a decoded numeric *zero* also does not count as meaningful (it is byte-for-byte indistinguishable from unwritten padding reinterpreted as that column type — a real false positive this exact check was written to close, and one `looks_like_padding` alone cannot catch).
- `EseDb::row_history(table, key_columns)` groups a table's live and recovered rows by caller-supplied key columns, so every version of "the same" logical row is visible together, with any disagreement surfaced (`RowHistory::is_disputed`) rather than resolved to one answer. The key is caller-supplied, not auto-detected, because this crate does not yet decode index key specifications from the catalog. Stays an inherent method rather than `RecoverRows::row_history`, which the trait documents as log-replay-derived prior versions — a mechanism this crate deliberately does not implement (see below); that trait method is left at its `EmptyRows` default instead of claiming it.
- `ese::recovery::sidecar::export_recovered`/`export_recovered_to_files` — opt-in export of recovered rows to caller-supplied writers (or paths), through `forensic_rs::pipeline::sinks::ProvenanceJsonlSink`: each row gets a real `forensic_rs::provenance::ProvenanceId` minted from a `ProvenanceStore`, with `Confidence` graded by the framework from `(Acquisition, Recovery)` rather than asserted by this crate, and a `ProvenanceSideTable` written to the sidecar at `finalize()`. Still never written by default or implicitly, matching the framework's stated policy that writing evidence-derived bytes to disk is an examiner's decision. Each record's `Locus` is emitted as explicit fields (`ese.page`/`ese.slot`/`ese.offset`) plus a deterministic `EventId`, since `Locus` itself is instance-level data that never reaches the provenance side table.
- `EseLogSetFactory` (`src/ese/format.rs`) — a `forensic_rs::traits::format::FormatFactory` yielding `Mounted::FileSet(FileSet)`: groups an ESE database with its transaction logs, checkpoint, flush map, and reserved logs purely by filename shape, reporting addresses (`EvidenceLocator`s via `MountContext::sibling_locator`) rather than open handles. A second, independent factory alongside `EseFormatFactory` — a FileSet factory is not a Database factory, so a resolver registers both and asks for each `MountKind` separately.
- `examples/log_set.rs`, `examples/recover_rows.rs`, `examples/row_history.rs` — runnable demonstrations of the above; `examples/mount_ese.rs` additionally demonstrates `EseLogSetFactory`'s `Mounted::FileSet`.

### Changed

- **Breaking**: `Header::position`/`attach_position`/`detach_position` retyped from a flat `u64` to `Lgpos`. `Header::required_log: u64` replaced by `min_required_generation: u32`/`max_required_generation: u32` (the low/high dwords of the same packed pair). Both packed values were previously exposed as opaque integers a caller had to split by hand; the retype is lossless (`Lgpos::from_u64_le`/`to_u64_le` round-trip exactly) but is a source-breaking change for any code matching the old field types.
- `Header` gains `database_signature`/`log_signature` (`Signature`) and six `BackupInfo`-typed backup blocks (`previous_full_backup`, `previous_incremental_backup`, `current_full_backup`, `current_shadow_copy_backup`, `previous_copy_backup`, `pevious_differential_backup`) — all previously parsed into `HeaderRpr` and silently dropped before reaching the public `Header`.
- **Breaking**: `EseDb::recovered_rows`/`recovered_slack_rows` (inherent methods returning `(Vec<RecoveredRow>, RecoveryStats)`) are gone, replaced by the `RecoverRows` trait implementation described above. `RecoveredRow` is now a type alias for `forensic_rs::recovery::Recovered<Row>` (no `Deref` — use `.value()`/`.into_value()`) instead of a crate-local struct, and the old `RowSource` enum is gone in favour of `forensic_rs::provenance::Locus` (`recovery::tagged_locus(page, tag)` builds `Locus::Record`; `recovery::slack_locus(page, offset)` builds `Locus::PageOffset` — a slack candidate has a real page, just no tag, so it is not flattened to a bare `RawOffset`). The underlying scan functions (`recovery::defunct::recover_defunct_rows`, `recovery::slack::recover_slack_rows`) are unchanged in shape and still public; their `RecoveryStats` now also reaches the trait boundary via `ForensicRows::scan_report()` (`RecoveryStats::to_report()`), so a generic caller can see how much ground a recovery scan covered, not just its rows.
- **Breaking, forensic-soundness fix**: `RowIter` (driving `Table::iter_rows`/`EseDb`'s `ForensicRows` cursor) now skips `TAG_DEFUNCT`-tagged entries, so ordinary iteration is a true allocated-only view — required for `ForensicRows::allocated()` to be truthful (a defunct row previously reported `allocated() == true`, a false confidence claim). `LeafPageEntry::leaf_entries` itself still decodes every tag, live or defunct, tagged with a new `tag_index`/`defunct` field — it stays the primitive `recovery::defunct` depends on; `RowIter` is what filters. Verified on `artifacts/sru/SRUDB.dat` that this changes no row counts (zero defunct tags are reachable from any live tree there), but it is a behavior change for a database that does have one.
- **Breaking**: `src/ese/log/source.rs` (`LogSetSource`, `DirLogSetSource`, `VfsLogSetSource`, `InMemoryLogSetSource`) is removed. `EseLogSet` discovery now drives `forensic_rs::traits::format::MountContext`'s sibling-discovery mechanics directly; `EseLogSet::discover`/`discover_in` keep their old signatures, and `EseLogSet::discover_via_mount_context(&MountContext)` is new. A directory holding more than one distinct `signLog` now leaves every discovered set's `flush_maps`/`reserves` empty rather than duplicating the same (attribution-ambiguous) members into every set.
- **Dependency**: now built against `forensic-rs` 0.14.0's `RecoverRows`/`Recovered`/`FileSet`/`MountContext` sibling-discovery seams — still unreleased at the time of this change; see the repository's `.cargo/config.toml` path patch.

### Fixed

- **Documentation**: `.jfm` was described as a mountable ESE database (`.mdb`/`.edb`/`.dat`/`.jfm`) in `src/lib.rs`, `src/ese/format.rs`, and `AGENTS.md`. It is not — confirmed `SRUDB.jfm`'s magic word at offset 4 is `3`, not the ESE header signature `0x89abcdef`, so `EseFormatFactory::probe` has always correctly scored it `ProbeScore::No`. A `.jfm` is a flush map belonging to a database, parsed separately via `ese::log::flushmap::FlushMap`.

### Discovered, not yet acted on

- On `artifacts/sru/SRUDB.dat`, 14 pages look defunct-tagged under a naive whole-file scan, and a separate whole-file scan finds 537 KB of non-zero page slack — but **neither** is reachable from any table's current B-tree (data, LV, or catalog). Both `recovery::defunct` and `recovery::slack` correctly report zero for this fixture (verified twice over, not a bug — see each module's `real_srum_fixture_*` tests, and `slack`'s note that the region-finding now also covers interior gaps, not just trailing ones). The actual recoverable content here sits in fully unlinked (freed) pages, or pages belonging to untracked trees (secondary indexes) — a materially riskier recovery source needing its own admission gate, since an orphaned page's original owning table can't be read off it directly without guessing a schema.
- Individual transaction-log-record (LR) decoding, `.jfm`'s page-flush-state bitmap, the log data-sector checksum algorithm, and log replay are all out of scope for this release — see `src/ese/log/mod.rs`'s module documentation for why each was deliberately not attempted. Log-borne row recovery (a lighter-weight alternative once considered) was also skipped for the same reason: it would need the identical LR-decoding capability. This is also why `RecoverRows::row_history` is left at its trait default rather than implemented.

## [0.2.0] - Unreleased

### Added

- `forensic_rs::traits::db::{ForensicDb, ForensicTable, ForensicRows}` implementation for `EseDb` (`src/ese/forensic_db.rs`), replacing the pre-0.14 `SqlDb`/`SqlStatement` bridge that forensic-rs 0.14 removed.
- `EseFormatFactory` (`forensic_rs::traits::format::FormatFactory`) — content-sniffs and mounts ESE files as `Mounted::Database` without the caller needing to know the format in advance. Streams pages on demand for files larger than the resolver's in-memory budget; slurps smaller files for zero-copy access.
- `EseDb::from_virtual_file` and a `VirtualFileReader` `PageReader` implementation over `forensic_rs::traits::vfs::VirtualFile`.
- `SrumDatabase::from_db` to build a SRUM view from an already-open `EseDb` (e.g. one mounted through `EseFormatFactory`).
- `ColumnType::forensic_type()` mapping to `forensic_rs::traits::db::ForensicColumnType`.
- A shared, cycle-safe B-tree traversal (`src/ese/tree.rs`) used by the catalog, long-value store, and table row iterator, replacing three independent, recursion-depth-bounded (but not visited-set-bounded) traversals.
- Byte-literal unit tests for every untrusted-input parser reachable from `EseDb::open()` (leaf/branch entry bounds, header signature/page-size validation, page-header checksum extension, B-tree cycle termination).
- `LICENSE`, this `CHANGELOG.md`, `AGENTS.md`, and a 3-OS CI workflow (`.github/workflows/rust.yml`).

### Changed

- **Breaking**: bumped to `forensic-rs = "0.14"`, Rust edition 2024, `rust-version = "1.87"`.
- **Breaking**: `EseDb::table()`, `SrumDatabase::open()`, and all 8 `SrumDatabase` per-table accessors now return `ForensicResult<_>` instead of `Option<_>`, so a caller can distinguish "file unreadable" from "table not found" from "database corrupt" instead of a bare `None`.
- **Breaking**: `Filetime` replaced by `forensic_rs::utils::time::ForensicTimestamp` throughout the public API (`Header`'s date fields, `ColumnValue`/`OwnedColumnValue::DateTime`, `Row::get_datetime`, every SRUM record's `timestamp` field, `TimelineEvent::timestamp()`).
- **Breaking**: `Header::page_to_file_offset` returns `ForensicResult<u64>` (checked arithmetic) instead of an unchecked `u64`.
- **Fixed (critical, forensic-soundness)**: ESE `DateTime` columns (`JET_coltypDateTime`) were decoded as a raw Win32 FILETIME 64-bit integer. Per the JET/ESE specification this column type is actually an 8-byte IEEE-754 double — an OLE Automation date (days since 1899-12-30). This silently produced wildly wrong timestamps (e.g. a real SRUM record's `TimeStamp` decoded to the year 16419 instead of 2020) for every SRUM/UAL/any-ESE-table row with a `DateTime` column, since the crate's first commit. Fixed via `ForensicTimestamp::try_from_ole_date`; an out-of-range value now degrades to an absent column instead of fabricating a substitute.
- **Fixed (critical, forensic-soundness)**: the ESE header's `LogTime` → timestamp conversion (`shutdown_datetime`/`attach_datetime`/etc.) treated `day` and `month` as 0-based; both are 1-based (verified against `artifacts/sru/SRUDB.dat`'s real header). This shifted every header timestamp by up to a month and a day, and rejected December (`month >= 12`) outright.
- **Fixed**: `PageHeader::from_buff` tested `version == 0x602`; the real ESE version is `0x620` (confirmed in the fixture), so the entire Win7 checksum/extended-header refinement was dead code for every real database. 16 KiB/32 KiB pages now correctly read the 40-byte Win7 extension and set `header_size = 80`; a stray `buffer[4..9]` slice into a 4-byte array (always failing, so both fields read as 0) is now `buffer[4..8]`.
- **Fixed**: `LeafPageEntry::new` and `BranchPageEntry::new` no longer panic (unchecked slice/overflow) on a maliciously or accidentally oversized key-size field read from untrusted page bytes.
- **Fixed**: `Header::from_buff` now validates the ESE magic signature and page size; previously any sufficiently long file parsed as a "valid" ESE header.
- **Fixed**: `RowIter`'s B-tree walk (and the catalog/long-value traversals) is now cycle-safe via a visited-page set, not just a recursion-depth counter — a self-referencing or cyclic branch page terminates instead of looping or doing exponential redundant work.
- **Fixed**: `root.rs`'s `number_of_pages` field read `data[0..4]` unconditionally, ignoring the leading alignment byte present on revision ≥ 0x14 (25-byte) root headers — every field after it was already offset-adjusted except this one.
- **Fixed**: a long-value B-tree with a segment gap or overlap no longer silently concatenates across the discontinuity (which would fabricate evidence); it now stops at the gap and logs a warning.
- **Fixed**: `sql_bridge.rs`'s `SELECT * FROM <table>` parser validated its prefix against an uppercased copy of the input but sliced the original string at a fixed byte offset — not length-preserving for non-ASCII input, and could panic on a non-char-boundary. Removed entirely (see below).
- Long-value B-trees are now cached per root page (`EseDb::lv_cache`) instead of being re-walked in full on every `iter_rows()` call.
- `EseDb` is now `Send + Sync` (required by `ForensicDb`): `FileReader` uses positioned reads (`pread`/`ReadFile`+offset) instead of a `RefCell<BufReader<File>>`, so no interior mutability is needed at all on that path.

### Removed

- `src/ese/sql_bridge.rs` (`SqlDb`/`SqlStatement` impl) — `forensic_rs::traits::sql` was removed upstream in 0.14. `ForensicDb::table(name)` now expresses the same access pattern natively, with no SQL-string parsing.
- `src/ese/page/key.rs` (`PageKeyRef`) and `Page::get_page_keys_if_root` — dead code with no live constructor path.
- The three unreferenced `PageHeader{Exchange2003,WinVista,Win7Ext}Repr` structs.
- `notify_low!`/`NotificationType` (removed upstream in 0.14) — per-entry parse-skip diagnostics now go through `forensic_rs::debug!`.

### Deprecated

- None new; the crate no longer uses forensic-rs's deprecated `ForensicError::bad_format_str`/`bad_format_string`/`missing_str` constructors, migrating to `ensure_format!`/`ensure_min_length!`/`invalid_format`/`missing_data`.

## [0.1.0]

Initial release: native ESE/JET Blue page and B-tree parser, SRUM reader, `forensic-rs` 0.13 `SqlDb` bridge.
